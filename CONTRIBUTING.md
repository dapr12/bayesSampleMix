# Contributing to bayesSampleMix

Thank you for your interest in improving bayesSampleMix. Bug reports,
questions and pull requests are all welcome.

## Reporting a bug

Please open an [issue](https://github.com/dapr12/bayesSampleMix/issues)
with a minimal reproducible example. The
[reprex](https://reprex.tidyverse.org/) package makes this easy. Include
the output of
[`sessionInfo()`](https://rdrr.io/r/utils/sessionInfo.html) and, for
sampler problems, the `seed` you used.

## Pull requests

1.  Fork the repository and create a branch from `main`.
2.  Install the development dependencies:
    `install.packages(c("devtools", "roxygen2", "testthat", "knitr", "rmarkdown", "coda"))`.
3.  Make your change. Documentation is generated by
    [roxygen2](https://roxygen2.r-lib.org/): edit the `#'` comments in
    `R/`, then run `devtools::document()`. Do not edit files in `man/`
    by hand.
4.  Add or update tests in `tests/testthat/`. Run `devtools::test()` and
    `devtools::check()` before opening the pull request.
5.  Add a bullet to the top of `NEWS.md` describing the change.

### Sampler changes

The test file `tests/testthat/test-equivalence.R` checks that seeded
fits reproduce the original research code draw for draw. If a change
deliberately alters a sampler, keep the original behaviour available
behind a
[`mixture_control()`](https://dapr12.github.io/bayesSampleMix/reference/mixture_control.md)
option (as was done for `m1_update`) and explain the change in
`NEWS.md`.

## Code of conduct

Please note that this project is released with a [Contributor Code of
Conduct](https://dapr12.github.io/bayesSampleMix/CODE_OF_CONDUCT.md). By
participating you agree to abide by its terms.
